# v0.9.0 Output Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publication-ready outputs — PDF/LaTeX export, Jupyter reproduce notebook, model cards, confidence-interval reporting, per-project METRICS.md.

**Architecture:** Four phases. (1) Uncertainty foundations: `IMetric.compute_with_ci`, `RunRecord.metrics_with_uncertainty`, CI rendering in labbook/report. (2) Deterministic artifacts: model cards + METRICS.md generated by pure code from findings.json/progress/criteria (NOT by agents — no API cost, fully testable, avoids turn-cap pressure). (3) Exports: pandoc-based PDF/LaTeX behind a `urika[export]` extra (`pypandoc`), nbformat-based reproduce.ipynb (nbformat already a transitive dep — verify and pin). (4) Surface parity + docs + smoke.

**Key design constraints (from the 2026-06-10 code map):**
- Agents compute metrics themselves in generated scripts; `IMetric` is a library FOR agents + tools. CI support = library method + prompt requirement + parsing/rendering, not a runtime hook.
- All narrative artifacts go through `core/report_writer.write_versioned()` — exports must too.
- Pandoc binary is NOT guaranteed (absent on the dev box): `--format latex` must work with pypandoc alone; `--format pdf` needs a TeX engine — fail with an actionable install message, never a traceback. Tests: unit-test with pypandoc mocked; integration tests gated `pytest.importorskip("pypandoc")` + `shutil.which("pandoc")`.
- Artifact names: `projectbook/final-report.pdf|.tex`, `projectbook/reproduce.ipynb`, `projectbook/METRICS.md`, `methods/<method>_model_card.md`.
- Audience modes apply to model cards and CI rendering prose.
- Conventions from the v0.8.0 plan apply: TDD, one commit per task, exact messages, NO Co-Authored-By, ruff before commit, `URIKA_SKIP_SMOKE=1 pytest <target> -q` only, read neighboring tests first.

## Phase 1 — Uncertainty foundations

### Task 1.1: `IMetric.compute_with_ci`
**Files:** `src/urika/evaluation/metrics/base.py` (+ concrete metric classes only if needed), `tests/test_evaluation/test_metrics_ci.py` (new)
**Spec:** Add a concrete (non-abstract) method on the ABC so every existing metric inherits it:
```python
def compute_with_ci(self, y_true, y_pred, *, confidence: float = 0.95,
                    n_boot: int = 2000, seed: int | None = 0) -> dict:
    """{"value": float, "ci_lower": float, "ci_upper": float,
        "confidence": float, "method": "bootstrap-percentile", "n_boot": int}
    Pairwise bootstrap resample of (y_true, y_pred); percentile interval
    of self.compute() over resamples. Deterministic for a given seed.
    Raises ValueError on len < 3 or length mismatch."""
```
Use numpy only (already a dep). Edge cases: degenerate resamples that raise inside `compute()` are skipped (count them; if >20% of resamples fail, raise ValueError with a clear message). Tests: deterministic for fixed seed; interval contains point value for R2/RMSE on a known dataset; tighter interval with larger n; mismatch/short-input ValueError; degenerate-skip behavior.
Commit: `feat(evaluation): IMetric.compute_with_ci bootstrap confidence intervals`

### Task 1.2: `RunRecord.metrics_with_uncertainty` + parsing + task-agent prompt

**Spec:** New field `metrics_with_uncertainty: dict[str, dict] = field(default_factory=dict)` — value shape `{"value", "ci_lower", "ci_upper", "confidence"}`. ## Phase 3 — Exports

### Task 3.1: Pandoc export module
**Files:** Create `src/urika/core/export.py`; `pyproject.toml` (add extra `export = ["pypandoc>=1.13"]` with a comment; do NOT use pypandoc_binary — comment why: bundles a fixed pandoc, heavy; users likely have distro pandoc); tests `tests/test_core/test_export.py` (new)
**Spec:**
```python
class ExportError(RuntimeError): ...
def export_markdown(md_path: Path, fmt: str, out_dir: Path | None = None) -> Path:
    """fmt in {"latex","pdf"}. Returns written path (versioned via write_versioned
    for .tex; pdf written then versioned-copy pattern — read write_versioned to
    integrate binary-safely; if it is text-only, version the .tex and write the
    .pdf unversioned with a timestamped sibling)."""
```
- Missing pypandoc → ExportError("PDF/LaTeX export needs the export extra: pip install urika[export]").
- pypandoc present, pandoc binary missing → use `pypandoc.download_pandoc()`? NO — ExportError with the distro install hint (apt/brew/choco) — keep zero magic downloads.
- fmt=pdf and no TeX engine → catch pandoc's error, ExportError("PDF needs a LaTeX engine (e.g. texlive: sudo apt install texlive-latex-recommended); `--format latex` works without one").
- LaTeX template: pandoc defaults + a small header include (`src/urika/templates/export/header.tex`) setting margins + a sans title font to echo the reveal.js aesthetic; resource-path set to the project dir so relative figure links resolve.
Unit tests mock pypandoc (capture args: to-format, resource-path, header include); error-path tests for all three ExportErrors; integration test `@pytest.mark.integration` gated on importorskip + which("pandoc") doing a real md→tex conversion and asserting `\documentclass` in output.
Commit: `feat(export): pandoc-based markdown→LaTeX/PDF with urika[export] extra`
