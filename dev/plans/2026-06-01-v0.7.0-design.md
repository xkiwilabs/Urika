# v0.7.0 — Multi-Provider Model Adapters Design

**Authored:** 2026-06-01.
**Slots into:** `dev/plans/2026-05-02-roadmap-to-v1.0.md` as v0.7.0 (next minor after v0.6.0).
**Status:** Designed; ready for writing-plans.
**Estimated effort:** ~13 dev-days (roadmap budget ~2 weeks).

## Goal

Ship OpenAI + Google agent backends alongside the existing Claude
adapter. After this release the same Urika project can run experiments
against Anthropic, OpenAI, or Google models, and users can mix providers
per agent role (e.g. planner=Anthropic, task=OpenAI, advisor=Google).
**Validates the `urika.runners` ABC against two independent SDKs before
v1.0 freezes the public API** — the v0.4 abstraction is real but has
only one consumer today.

Plus: add the Anthropic subscription auth path the May 13 2026
announcement legitimized (effective June 15 2026), so users with Pro /
Max plans can use their existing subscription credit pool instead of
paying API rates separately.

## Locked decisions (brainstorm 2026-06-01)

1. **Scope = direct OpenAI + Google adapters.** Not a Pi / LiteLLM-style
   universal proxy. Two independent SDKs is the honest stress-test of
   the `urika.runners` ABC.
2. **Tool layer = single Urika source of truth.** Ship `urika.agents.tools`
   with Bash / Read / Write / Grep / Glob / Edit + the existing
   `urika.agents.permission.SecurityPolicy` enforcement. Claude adapter
   keeps delegating to SDK built-ins; OpenAI / Google adapters expose
   the Urika tools as SDK function calls.
3. **Cost tracking = per-adapter, shared pricing table.** Each adapter
   parses its SDK's usage shape into the existing
   `AgentResult.usage`. `urika.agents.pricing.cost_for(model, in_tok,
   out_tok)` is the single source of $-per-1M-tokens truth.
4. **Default model strategy = mirror the reasoning / execution split**
   that already works for Anthropic (Opus reasoning agents, Sonnet
   execution agents).
5. **Specific defaults:**
   - **Anthropic:** `claude-opus-4-7` (reasoning) + `claude-sonnet-4-5`
     (execution). Unchanged.
   - **OpenAI:** `gpt-5.4` (reasoning) + `gpt-5.4-mini` (execution).
     ~3× cheaper on execution-agent tokens; mini is fast enough for tool
     / code work per OpenAI's own positioning. `gpt-5.4-nano` is
     available for very simple format-conversion agents but defer that
     tuning post-v0.7.
   - **Google:** `gemini-3-pro` (reasoning) + `gemini-3-flash`
     (execution). ~10× cheaper on execution-agent tokens.
6. **Testing = unit tests with mocked SDKs + extend the e2e smoke
   script.** Each adapter gets a unit-test suite that mocks its SDK's
   request surface (same pattern as the existing
   `tests/test_agents/test_claude_sdk*.py`). Extend
   `dev/scripts/smoke-v04-e2e-open.sh` with
   `--provider openai|google|anthropic` and a `--mixed-providers`
   flag; operator runs all four before tagging.
7. **Anthropic auth = API key + subscription (NEW post-June-15).** Both
   paths supported in v0.7. The compliance check is relaxed for users
   who opt into subscription mode via config.
8. **Google SDK = `google-adk` (Agent Development Kit), not the lower-
   level `google-genai`.** Symmetric with the OpenAI Agents SDK pick;
   first-party agent framework so the adapter is thinner. Trade-off:
   ADK's opinionated multi-agent / session primitives are ignored where
   they conflict with Urika's existing orchestrator.

## What's already in tree

- `src/urika/agents/runner.py` — `AgentRunner` ABC + `AgentResult`
  dataclass. Public surface, untouched in v0.7.
- `src/urika/agents/config.py` — `AgentConfig` (name, system_prompt,
  model, env, security policy, etc.). Untouched.
- `src/urika/agents/adapters/claude_sdk.py` — current and only adapter.
  Wraps `claude-agent-sdk` (v0.2.87 as of 2026-05-23). Extended in v0.7
  to support subscription auth.
- `src/urika/core/compliance.py:require_api_key` — refuses
  Anthropic SDK calls without `ANTHROPIC_API_KEY`. Relaxed in v0.7 for
  subscription mode.
- `src/urika/core/known_secrets.py` — vault metadata. Extended with
  `OPENAI_API_KEY` and `GEMINI_API_KEY` so the vault's auto-load picks
  them up via `urika.core.secrets.load_secrets()`.

## Adapter contract

Each adapter implements `AgentRunner.run(config, user_message) -> AgentResult`.
The contract is unchanged — only new implementations.

The general flow each adapter follows:

1. Translate `AgentConfig.system_prompt` + the per-turn `user_message`
   into the SDK's request shape.
2. Expose each tool from `urika.agents.tools.ToolRegistry` as a function
   call in the SDK's format:
   - Claude SDK: builds in `Bash` / `Read` / `Write` etc. natively;
     adapter just sets the `SecurityPolicy`.
   - OpenAI Agents SDK: `@function_tool` decorators on Python wrappers
     that delegate to `urika.agents.tools`.
   - Google ADK: `Tool` declarations on Python wrappers that delegate
     to `urika.agents.tools`.
3. Drive the agent loop until the SDK reports the agent finished (or
   `config.max_turns` is reached). For Claude + OpenAI + ADK the SDKs
   handle the loop themselves; the adapter just collects messages and
   tool calls into the result.
4. Parse usage → cost via `urika.agents.pricing.cost_for(model,
   input_tokens, output_tokens)`. Return `AgentResult(text_output,
   success, usage, error)` — the same shape `claude_sdk.py` returns
   today.

## Tool layer — `urika.agents.tools`

A single package with all the file-system / shell tools the agents
need. Each tool is a Python function:

```python
def bash(cmd: str, *, security: SecurityPolicy, project_dir: Path,
         timeout_seconds: int = 600) -> ToolResult: ...
def read(path: str, *, security: SecurityPolicy) -> ToolResult: ...
def write(path: str, content: str, *, security: SecurityPolicy) -> ToolResult: ...
def grep(pattern: str, path: str, *, security: SecurityPolicy) -> ToolResult: ...
def glob(pattern: str, *, security: SecurityPolicy) -> ToolResult: ...
def edit(path: str, old_string: str, new_string: str, *,
         security: SecurityPolicy) -> ToolResult: ...
```

Each function takes the `SecurityPolicy` and enforces it inline — the
same checks (`shlex` tokenization, metacharacter rejection, writable-
dir validation, path symlink resolution) the v0.4 sweep landed for the
Claude SDK's `can_use_tool` callback. Single source of truth means a
fix in v0.5.x-class bugs propagates everywhere automatically.

The Claude adapter doesn't call these functions directly — the SDK
provides its own built-in tools, and the adapter installs a
`can_use_tool` callback that consults the same `SecurityPolicy`. But
the security logic itself lives in `urika.agents.tools` and is shared
across adapters, so they all enforce the same policy.

`ToolResult` is a small dataclass: `ok: bool`, `output: str`,
`error: str | None`, `exit_code: int | None`.

## Routing — model name → adapter

`urika.agents.registry.runner_for(model_string) -> AgentRunner` does
prefix matching:

| Pattern | Adapter |
|---|---|
| `claude-*` | `ClaudeSDKRunner` |
| `gpt-*` / `o3` / `o4` / `o5` | `OpenAIAgentsRunner` |
| `gemini-*` | `GoogleADKRunner` |

Per-agent model strings in `urika.toml` are unchanged — already just
strings (`[agents.planning] model = "claude-opus-4-7"`). The dashboard
Models tab adds a Provider dropdown that filters the model picker;
the dropdown's value is implicit in the model string, not stored
separately.

`get_agent_model(agent_name, runtime_config)` (existing helper in
`agents/config.py`) returns the model string; the orchestrator passes
it through `registry.runner_for(model)` to get the runner. Same
`AgentConfig` flows through unchanged.

## Auth — the asymmetric reality

**Anthropic — API key OR subscription:**

- *API key path (existing, unchanged):* `ANTHROPIC_API_KEY` set in env;
  the SDK uses it; `compliance.require_api_key` passes.
- *Subscription path (NEW, post-June-15 2026):* user runs
  `claude login` in their terminal (the CLI's own OAuth flow), then
  adds `[anthropic] auth = "subscription"` to `~/.urika/settings.toml`.
  Urika's compliance check accepts subscription mode and lets the
  Claude SDK spawn the `claude` CLI WITHOUT setting
  `ANTHROPIC_API_KEY` in env — the CLI uses its stored OAuth token.
  Credits consumed from the user's Pro / Max Agent SDK credit pool
  (`$20` / `$100` / `$200` monthly, billed at API rates, non-rollover).

  The compliance change is:

  ```python
  # core/compliance.py
  def require_api_key(model: str | None, agent_env: Mapping[str, str] | None) -> None:
      if not is_anthropic_cloud_call(model, agent_env):
          return
      if has_api_key(agent_env):
          return
      # NEW: subscription mode is now legitimate post-June-15
      from urika.core.settings import get_preference
      if get_preference("anthropic_auth") == "subscription":
          return
      raise APIKeyRequiredError(...)
  ```

  `urika config anthropic` is the interactive setup. It prompts:
  `api_key` (current) or `subscription` (new). The subscription branch
  prints `Run 'claude login' in your terminal first, then re-run this
  command.` and waits for confirmation. On confirmation it writes the
  setting and runs a quick `claude --version` to verify the CLI is
  available and authenticated.

**OpenAI — API key only (forced by OpenAI):**

- `OPENAI_API_KEY` env var; auto-loaded via vault.
- ChatGPT Plus subscription is product-separated from API access and
  cannot be used. Document the asymmetry prominently in the release
  notes — this is OpenAI's choice, not Urika's.

**Google — API key only (ToS-forbidden otherwise):**

- `GEMINI_API_KEY` (or `GOOGLE_API_KEY` as alias) env var; auto-loaded
  via vault.
- Google explicitly bans third-party subscription piggyback. They
  mass-suspended Ultra subscribers who used such tools in February
  2026. Document prominently: *"Google AI Pro / Ultra subscriptions
  cannot be used to authenticate Urika — Google's ToS forbids it.
  Urika requires a Gemini API key from Google AI Studio or Vertex
  AI."*

**Vault wiring:** `src/urika/core/known_secrets.py` gets entries for
`OPENAI_API_KEY` and `GEMINI_API_KEY` so the vault auto-loads them
via `urika.core.secrets.load_secrets()` on every CLI invocation. The
dashboard's Secrets tab lists them automatically (no schema change —
it already iterates `known_secrets.LLM_PROVIDERS`).

## Cost / usage

`urika.agents.pricing` ships a small table:

```python
# urika.agents.pricing
PRICES = {
    # Anthropic — input $/1M, output $/1M
    "claude-opus-4-7":   (15.0,  75.0),
    "claude-sonnet-4-5": (3.0,   15.0),
    # OpenAI
    "gpt-5.4":           (2.50,  15.0),
    "gpt-5.4-mini":      (0.75,  4.50),
    "gpt-5.4-nano":      (0.20,  1.25),
    "gpt-5.4-pro":       (30.0,  180.0),
    "gpt-5.4-thinking":  (2.50,  15.0),  # adjust when published
    # Google
    "gemini-3-pro":      (5.0,   25.0),  # placeholder; verify at impl time
    "gemini-3-flash":    (0.50,  2.50),  # placeholder; verify at impl time
}


def cost_for(model: str, input_tokens: int, output_tokens: int) -> float:
    rates = PRICES.get(model)
    if rates is None:
        return 0.0
    in_rate, out_rate = rates
    return (input_tokens / 1_000_000) * in_rate + (output_tokens / 1_000_000) * out_rate
```

The Gemini prices are placeholders — verify against Google's published
pricing at implementation time and update.

**Special case: subscription-mode Anthropic.** No per-call $ is meaningful
because credits are consumed server-side from the credit pool, not
billed per token. The adapter returns:

```python
AgentResult(
    ...,
    usage={
        "input_tokens": N,
        "output_tokens": M,
        "cost_usd": None,
        "mode": "subscription",
    },
)
```

The dashboard usage page renders `subscription credits` instead of `$`
on rows with `mode == "subscription"`. Aggregate cost is reported only
for API-key-mode calls.

## Adapter implementation notes

### OpenAI adapter (`openai_agents.py`)

The OpenAI Agents SDK gives us an `Agent` class with `name`,
`instructions` (system prompt), `model`, and a `tools` list. The
adapter:

```python
class OpenAIAgentsRunner(AgentRunner):
    async def run(self, config: AgentConfig, prompt: str) -> AgentResult:
        from agents import Agent, Runner, function_tool
        from urika.agents.tools import ToolRegistry

        # Wrap each Urika tool as a `@function_tool` for the SDK
        tools = [_wrap_tool(t, config.security)
                 for t in ToolRegistry.for_role(config.name)]
        agent = Agent(
            name=config.name,
            instructions=config.system_prompt,
            model=config.model,
            tools=tools,
        )
        result = await Runner.run(agent, prompt, max_turns=config.max_turns)
        # ... usage extraction, cost calc, return AgentResult
```

Tool wrapping converts our `bash(cmd, *, security, project_dir, ...) ->
ToolResult` into something the SDK can register — a thin
`@function_tool` decorator around a lambda that closes over `security`
and `project_dir`.

### Google adapter (`google_adk.py`)

ADK gives us an `Agent` class with `name`, `instruction`, `model`, and
`tools`. Structurally similar to OpenAI's:

```python
class GoogleADKRunner(AgentRunner):
    async def run(self, config: AgentConfig, prompt: str) -> AgentResult:
        from google.adk.agents import Agent
        from google.adk.runners import Runner
        from urika.agents.tools import ToolRegistry

        tools = [_wrap_adk_tool(t, config.security)
                 for t in ToolRegistry.for_role(config.name)]
        agent = Agent(
            name=config.name,
            instruction=config.system_prompt,
            model=config.model,
            tools=tools,
        )
        runner = Runner(agent=agent)
        async for event in runner.run_async(prompt):
            # accumulate events into AgentResult
            ...
```

ADK exposes a streaming runner; the adapter just consumes the event
stream and assembles the result.

### Claude adapter changes (`claude_sdk.py`)

The subscription auth path adds:

```python
# In ClaudeSDKRunner.run() before spawning the SDK subprocess
from urika.core.settings import get_preference
auth_mode = get_preference("anthropic_auth", default="api_key")
if auth_mode == "subscription":
    # Don't set ANTHROPIC_API_KEY in the child env — let the
    # `claude` CLI use its stored OAuth token from `claude login`.
    env_for_child.pop("ANTHROPIC_API_KEY", None)
    # The SDK's compliance scrubber must NOT zero the OAuth token
    # env vars in subscription mode.
    skip_oauth_scrub = True
else:
    # API key path: ensure ANTHROPIC_API_KEY is present (existing).
    skip_oauth_scrub = False
```

The `compliance.scrub_oauth_env` helper grows a `skip` parameter (or
the auth-mode-aware logic stays in the adapter — to be decided at
implementation time). Either way, subscription mode means OAuth tokens
flow through to the child process.

same semantics.

## Testing strategy

### Unit tests (per adapter)

Each adapter gets a test file `tests/test_agents/test_<adapter>.py`
that mocks the SDK's request surface. Pattern mirrors the existing
`tests/test_agents/test_claude_sdk_runner.py`:

- A `FakeSDK` (or `monkeypatch` over the SDK client) returns canned
  responses.
- Assert the adapter translates `AgentConfig` correctly.
- Assert tool calls are exposed in the SDK's expected format.
- Assert usage parsing produces the right `AgentResult.usage`.
- Assert errors are returned (not raised) per the `AgentResult` contract.

### Tool-layer tests

`tests/test_agents/test_tools_*.py` cover Bash / Read / Write / Grep /
Glob / Edit under `SecurityPolicy`. Many of these mirror tests already
in `tests/test_security/` — the new tests just exercise the same
policy through the new tool functions instead of through the Claude
SDK's `can_use_tool` callback.

### Cross-surface routing tests

`tests/test_agents/test_registry.py` — model-prefix matching:

- `runner_for("claude-opus-4-7")` returns `ClaudeSDKRunner`
- `runner_for("gpt-5.4")` returns `OpenAIAgentsRunner`
- `runner_for("gemini-3-pro")` returns `GoogleADKRunner`
- `runner_for("unknown-model")` raises a clear error

### Real-API smoke (operator-driven, opt-in)

Extend `dev/scripts/smoke-v04-e2e-open.sh` with new flags:

- `--provider openai|google|anthropic` — runs the full open-mode e2e
  with all agents pinned to that provider.
- `--mixed-providers` — pins planner=Anthropic, task=OpenAI,
  advisor=Google. Exercises cross-provider routing through one
  experiment.
- `--anthropic-auth subscription|api_key` — for the Anthropic-only
  run, picks which auth path. Subscription mode requires the operator
  to have run `claude login` first.

Operator runs all four combinations before tagging v0.7. Expected
cost: ~$2-5 per run (cheap models, single experiment, 3 turns).

## Cut criterion

The release ships only when ALL of:

1. **A complete experiment runs end-to-end on each of Anthropic,
   OpenAI, and Google** against the same behavioral-data fixture
   (Stroop), producing equivalent artifact sets (same projectbook
   shape — findings.json, leaderboard.json, reproduce.sh, etc.). The
   methods chosen and decisions made will differ across providers
   (different LLMs make different choices on the same data), but the
   artifact STRUCTURE is identical.

2. **A mixed-provider 5-turn experiment** (planner=Anthropic,
   task=OpenAI, advisor=Google) runs without errors and records
   correct usage / cost per backend in `progress.json`.

3. **Anthropic subscription auth path verified by a real operator
   session** against a Pro or Max account post-June-15-2026.
   `urika config anthropic` interactive setup succeeds; subsequent
   `urika run` consumes from the credit pool (verified via
   `claude --status` or the equivalent SDK call).

4. **OpenAI Plus subscription cleanly rejected** with the documented
   message pointing to API-key setup. Verified by running
   `urika config openai` with an attempt at subscription mode.

5. **Google subscription path explicitly NOT exposed** — there is no
   way to misconfigure Urika into using a Google subscription. Vault
   only accepts API keys for this provider.

6. **Full pytest green** including the new per-adapter unit suites
   and tool-layer tests.

7. **An existing v0.6.x project upgrades to v0.7.0 with zero config
   changes and continues to run unchanged** — see the next section.

## Backward compatibility

v0.7.0 is a strict superset of v0.6.x for existing Claude SDK users.
After `pip install --upgrade urika`:

- **`urika.toml`** — schema unchanged. Existing
  `[agents.*] model = "claude-..."` strings continue to work; the new
  `registry.runner_for("claude-*")` routes them to `ClaudeSDKRunner`,
  the same class they hit today. No migration step.
- **`~/.urika/settings.toml`** — gains ONE new optional key,
  `[anthropic] auth = "api_key" | "subscription"`. Default is
  `"api_key"` (existing behavior). Existing users never need to touch
  it.
- **Compliance check** (`compliance.require_api_key`) — the existing
  "ANTHROPIC_API_KEY must be set" branch is preserved exactly. The
  subscription branch only fires when `auth = "subscription"` is
  written by the user.
- **Vault** — adds `OPENAI_API_KEY` / `GEMINI_API_KEY` entries to
  `known_secrets.LLM_PROVIDERS`. Purely additive; the existing
  `ANTHROPIC_API_KEY` row is unchanged.
- **Dashboard Models tab** — gets a Provider filter, but defaults to
  "Anthropic" on first load so existing pages render identically.
- **Pricing table** — Claude rates unchanged; OpenAI/Google rows
  added. Per-project cost history continues to render correctly.
- **Tool layer** — the Claude adapter keeps delegating to the SDK's
  built-in tools and the existing `SecurityPolicy.can_use_tool`
  callback. The new `urika.agents.tools` package is only consumed by
  the OpenAI/Google adapters.

The only ways an existing Claude SDK user encounters v0.7 surface:
(a) they change a model string to `gpt-*` / `o3-o5` / `gemini-*`,
(b) they explicitly opt into Anthropic subscription auth, or
(c) they install `openai-agents` / `google-adk` as optional extras.

## Out of scope for v0.7.0

Deferred to v0.8+ if real demand surfaces:

- **LiteLLM-style universal proxy** — premature; only matters if we
  later want to support 4+ providers.
- **Pi (pi-ai) multi-provider runtime** — the older runtime-abstraction
  memory's broader vision. Not needed once three first-party adapters
  work.
- **OpenAI Assistants API or Codex App Server** — Agents SDK is the
  current first-party path; Assistants is being deprecated.
- **Provider-specific built-in tools** — Anthropic's `computer use`,
  OpenAI's `computer_use` model, Google's Live API. Not how Urika
  uses tools.
- **Plugin entry points for third-party adapters** — post-1.0 if a
  community adapter ever ships.
- **Multi-modal inputs** (images, audio, video) — not a Urika use case
  yet.
- **Azure OpenAI / Vertex AI** as alternate auth surfaces — enterprise
  feature; revisit in v0.8 if a paying user asks.
- **Cross-provider model migration tooling** — automatic "find the
  equivalent Google model for this Anthropic model" mapping. Manual
  user choice is fine for v0.7.

## Open questions to resolve at implementation time

These are *implementation-detail* unknowns the brainstorm couldn't
lock — they need the engineer to discover the answer from the SDK
docs / source while writing the adapter:

1. **OpenAI Agents SDK token-usage extraction.** The SDK abstracts the
   raw response; does it expose per-turn token counts cleanly, or do
   we need to drop down to the Responses API to get them? If the
   latter, the adapter may need a custom request hook.
2. **Google ADK opinionated session model.** ADK has Sessions and
   Memories as first-class concepts. Urika has its own session
   handling. The adapter may need to stub out ADK's session manager
   so Urika's stays authoritative.
3. **Gemini price-table verification.** The Gemini prices in
   `pricing.py` are placeholders — verify against Google's current
   published rates and update before tagging.
4. **`gpt-5.4-thinking` request shape.** Is it a model parameter or a
   separate request mode? Adjust the registry accordingly.
5. **ADK + Urika's `SecurityPolicy`.** ADK's built-in tool implementations
   (e.g. its own `code_execution`) bypass our policy. Adapter must
   register ONLY Urika's tools and disable ADK's built-ins.
